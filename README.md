### Шаг 1. Подготовка окружения
1. Откройте **VS Code**.
2. Откройте встроенный терминал (`Ctrl + ~`) и убедитесь, что используется **Git Bash** (в правом верхнем углу терминала можно выбрать оболочку).
3. Убедитесь, что у вас установлен и запущен **Docker Desktop** (или Docker Engine в Linux).

### Шаг 2. Запуск базы данных через Docker CLI
Вам нужна СУБД (например, MySQL или PostgreSQL). Давайте используем MySQL.
В терминале Git Bash выполните команду для запуска контейнера:
```bash
docker run --name lab5_db -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=lab5 -p 3306:3306 -d mysql:latest
```
*Подключитесь к базе данных через терминал или используйте расширение MySQL в VS Code для удобства:*
```bash
docker exec -it lab5_db mysql -u root -proot lab5
```

### Шаг 3. Процесс нормализации (Теория и практика)
Исходная таблица находится в **1НФ** (все значения атомарны), но имеет составной первичный ключ `(Код заказа, Код товара)`.

#### Переход во 2НФ (Устранение частичной зависимости)
Атрибуты должны зависеть от *всего* первичного ключа, а не от его части.
* `Дата`, `Код клиента`, `Имя клиента` зависят только от `Код заказа`.
* `Название товара`, `Цена`, `Код товарной классификации`, `Имя товарной классификации` зависят только от `Код товара`.
* `Количество` зависит от обоих (остаётся в связующей таблице).

**Результат 2НФ:**
1. `Заказы` (Код заказа, Дата, Код клиента, Имя клиента)
2. `Товары` (Код товара, Название товара, Цена, Код товарной классификации, Имя товарной классификации)
3. `Состав_заказа` (Код заказа, Код товара, Количество)

#### Переход в 3НФ (Устранение транзитивной зависимости)
Атрибуты не должны зависеть от других неключевых атрибутов.
* В таблице `Заказы`: `Имя клиента` зависит от `Код клиента` (транзитивная зависимость). Выносим клиентов отдельно.
* В таблице `Товары`: `Имя товарной классификации` зависит от `Код товарной классификации`. Выносим классификации отдельно.

**Итоговая схема 3НФ (5 таблиц):**
1. **Клиенты** (`Код клиента` [PK], `Имя клиента`)
2. **Классификации** (`Код классификации` [PK], `Имя классификации`)
3. **Товары** (`Код товара` [PK], `Название товара`, `Цена`, `Код классификации` [FK])
4. **Заказы** (`Код заказа` [PK], `Дата`, `Код клиента` [FK])
5. **Состав_заказа** (`Код заказа` [FK], `Код товара` [FK], `Количество`, PK: `(Код заказа, Код товара)`)

### Шаг 4. Написание SQL-скриптов (Ваши действия)
Теперь вам нужно написать SQL-запросы для создания этой структуры. *Именно эти запросы пойдут в ваш лог-файл.*

```sql
-- Создание таблиц 3НФ
CREATE TABLE Clients (
    client_id INT PRIMARY KEY,
    client_name VARCHAR(100) NOT NULL
);

CREATE TABLE Categories (
    category_id INT PRIMARY KEY,
    category_name VARCHAR(100) NOT NULL
);

CREATE TABLE Products (
    product_id INT PRIMARY KEY,
    product_name VARCHAR(100) NOT NULL,
    price DECIMAL(10, 2) NOT NULL,
    category_id INT,
    FOREIGN KEY (category_id) REFERENCES Categories(category_id)
);

CREATE TABLE Orders (
    order_id INT PRIMARY KEY,
    order_date DATE NOT NULL,
    client_id INT,
    FOREIGN KEY (client_id) REFERENCES Clients(client_id)
);

CREATE TABLE Order_Items (
    order_id INT,
    product_id INT,
    quantity INT NOT NULL,
    PRIMARY KEY (order_id, product_id),
    FOREIGN KEY (order_id) REFERENCES Orders(order_id),
    FOREIGN KEY (product_id) REFERENCES Products(product_id)
);
```
*(Примечание: если преподаватель требует строго русские названия полей, используйте их в бэктиках `` `Код заказа` ``, но в индустрии принято использовать английский транслит. Уточните этот момент, если сомневаетесь).*

### Шаг 5. Создание лога и дампа
По условию: *"лог-файл должен содержать только ваши действия"*. Это значит, что в логе не должно быть вывода консоли (таблиц, сообщений "Query OK"), **только сам SQL-код**, который вы вводили.

1. **Лог-файл (`actions.log` или `actions.sql`)**:
   Создайте в папке проекта файл `actions.sql` и скопируйте туда все ваши `CREATE TABLE`, `INSERT INTO` (если добавляли тестовые данные) и `SELECT` запросы.
2. **Дамп базы данных (`dump.sql`)**:
   Не выходя из Git Bash, сделайте дамп вашей базы данных из Docker-контейнера:
   ```bash
   docker exec lab5_db mysqldump -u root -proot lab5 > dump.sql
   ```
   *Теперь в вашей папке лежат файлы `dump.sql` и `actions.sql`.*
